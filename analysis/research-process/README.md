# Research-process analysis

This collection measures recorded construction progress and checking outcomes in
the AI-assisted search for a homogeneous mono-monostatic polyhedron. It uses the
[construction catalog](../../catalog/construction-history.md), selected scientific
reports, and a fresh replay of all ten cases saved with the C622 source package.

## Results and counting units

The public collection contains 898 report records and 174 research-direction
records. A report can contain several candidates or none; neither count measures
the number of construction attempts.

The 136 catalogued construction records have different retained acceptance labels:

| Row-level evidence | Records |
| --- | ---: |
| Explicit accepted status | 63 |
| Parallel accepted exact report | 5 |
| Status omitted in the retained row | 61 |
| Other explicit status | 7 |

The main chronology includes the first three categories: 129 rows and 55 strict
decreases in the running best mechanical complexity, from 1,026,460 on 4 September
to 622 on 15 September 2026. Restricting it to the 68 explicitly accepted rows gives
30 decreases, from 26,112 on 5 September to the same endpoint. Reports sharing a UTC
timestamp are grouped before counting a decrease; the initial record is not a
decrease. This restriction measures sensitivity to missing status labels. It does
not change the historical status of the earlier constructions.

Thirty-three catalog records link to public reconstruction packages. The catalog
has gaps on 11, 13 and 14 September. An empty date therefore does not establish
that no work occurred. Repeated counts do not establish identical geometry, and
consecutive records need not be parent and child.

On 13 October 2026, both supplied exact programs were rerun on all ten saved C622
cases. All twenty reports reproduced the expected outputs and the controls passed.
Six cases have strict counts (S,U,H)=(1,1,0); four are documented intermediates or
nonwinners. All have zero additional weak equilibria. This is the complete saved
ten-case collection, not ten independently sampled attempts or four overturned
success claims. Legacy case names use 2E; `mechanical_complexity` is recomputed as
V+E+F−S−U−H for every case.

Three historical numerical batches report 32 affine-search starts, 60 single-chain
solves and 60 opposed-chain solves, with no target-class result. The opposed-chain
batch reports 12 own-centroid closures. These are reported numerical outcomes,
separate from the freshly rerun exact collection. Selected failure episodes record
wrong-centroid screening and source-recovery problems; they are not a failure-rate
sample.

## Files

- `construction-records.json`: public catalog IDs, timestamps, sizes, status labels,
  package paths and source-journal line locations. Status labels restore information
  omitted from the first public catalog projection.
- `verification-cases.json`: the fresh ten-case census and exact report identities.
- `reported-search-batches.json`: method-specific counts and their scientific source.
- `failure-episodes.json`: selected documented errors and recovery outcomes.
- `summary.json`: aggregates and both progress series, generated by `analyze.py`.

## Reproduce

From the repository root, Python 3.11+ with its standard library is sufficient:

```sh
python3 analysis/research-process/analyze.py --output process-summary.json
```

To repeat the full exact collection and compare it with this census:

```sh
python3 -B -S C622/source/REPLAY.py --out ten-case-replay
python3 analysis/research-process/analyze.py --replay-dir ten-case-replay --output process-summary.json
```

Choose a new replay directory for each run. The analysis checks every case against
the preserved expected counts and, when fresh outputs are supplied, compares both
program reports with the exact saved report identities.
